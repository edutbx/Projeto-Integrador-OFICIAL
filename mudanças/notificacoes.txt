  SISTEMA DE NOTIFICAÇÕES — SOLICITAÇÃO DE CADASTRO
  Projeto: Saúde++
  Data: 14/03/2026
================================================================

VISÃO GERAL
-----------
Foi implementado um sistema de notificações para que médicos possam
solicitar cadastro diretamente pela tela de login, e o gestor do
sistema seja alertado em tempo real no painel administrativo.

Fluxo resumido:
  1. Médico acessa /login e clica em "Solicitar cadastro"
  2. Um modal abre pedindo nome, e-mail, CRM e mensagem
  3. Ao confirmar, uma notificação é salva no banco de dados (MongoDB)
  4. O gestor vê o sino no header com badge vermelho indicando novas notificações
  5. Ao clicar no sino, um painel exibe todas as solicitações com os dados do médico
  6. O gestor marca como lida e realiza o cadastro manualmente


================================================================
  BACKEND
================================================================

ARQUIVOS CRIADOS
----------------

1. backend/.../auth/model/Notificacao.java
   - Entidade MongoDB mapeada para a collection "notificacoes"
   - Campos:
       id            → ID gerado pelo MongoDB
       tipo          → sempre "SOLICITACAO_CADASTRO"
       nomeRemetente → nome do médico que solicitou
       emailRemetente→ e-mail de contato
       crm           → CRM do médico (opcional)
       mensagem      → observação adicional (opcional)
       dataHora      → data e hora do envio (LocalDateTime)
       lida          → false por padrão, true quando o gestor marca

2. backend/.../auth/repository/NotificacaoRepository.java
   - Interface que estende MongoRepository
   - Métodos:
       findAllByOrderByDataHoraDesc() → lista todas ordenadas pela mais recente
       countByLidaFalse()            → conta quantas ainda não foram lidas

3. backend/.../auth/dto/NotificacaoRequest.java
   - DTO (objeto de transferência) que recebe os dados do frontend
   - Campos: nomeRemetente, emailRemetente, crm, mensagem

4. backend/.../auth/controller/NotificacaoController.java
   - Controller REST com 4 endpoints:

       POST   /api/notificacoes              → público, cria a notificação
       GET    /api/notificacoes/admin        → admin, lista todas
       GET    /api/notificacoes/admin/count  → admin, retorna { naoLidas: N }
       PUT    /api/notificacoes/admin/{id}/lida → admin, marca como lida

   - Os endpoints /admin/* exigem ROLE_ADMIN via @PreAuthorize

ARQUIVOS MODIFICADOS
--------------------

5. backend/.../config/SecurityConfig.java
   - Adicionado "/api/notificacoes" na lista de rotas públicas (permitAll)
   - Isso permite que qualquer pessoa (sem login) envie uma solicitação

  SISTEMA DE PACIENTES — CRUD (GESTOR + MÉDICO)
  Projeto: Saúde++
  Data: 11/04/2026
================================================================

VISÃO GERAL
-----------
Foi implementado o CRUD completo de pacientes com os campos:
  - Nome
  - Idade
  - Endereço
  - Altura
  - Peso

Também foi feita a integração para:
  - Gestor cadastrar, buscar, editar e excluir pacientes
  - Médico consultar/listar pacientes

Preparação para próximos passos:
  - Estrutura pronta para vínculo com prontuário
  - Estrutura pronta para restringir visibilidade por médico/consulta no futuro

Fluxo resumido:
  1. Gestor acessa /gestor/pacientes
  2. Gestor cadastra paciente com os dados básicos
  3. Gestor pode buscar, editar e excluir paciente
  4. Médico acessa /medico/pacientes e consulta os pacientes cadastrados
  5. Atualmente todos os médicos visualizam todos os pacientes (regra temporária)


================================================================
  BACKEND
================================================================

ARQUIVOS CRIADOS
----------------

1. backend/.../auth/model/Paciente.java
   - Entidade MongoDB mapeada para a collection "pacientes"
   - Campos principais:
       id, nome, idade, endereco, altura, peso
   - Campos de preparação para evolução:
       medicoCrmReferencia
       medicoCrmsComAcesso (lista de médicos com potencial acesso)
       prontuarioAtualId
       ultimaAlteracaoProntuarioPorCrm
       ultimaAlteracaoProntuarioEm
   - Campos de auditoria:
       criadoPor, criadoEm, atualizadoPor, atualizadoEm

2. backend/.../auth/repository/PacienteRepository.java
   - Interface que estende MongoRepository para persistência dos pacientes

3. backend/.../auth/dto/PacienteRequest.java
   - DTO de entrada para criação/atualização
   - Validações:
       nome/endereco obrigatórios
       idade mínima 0
       altura e peso positivos

4. backend/.../auth/dto/PacienteResponse.java
   - DTO de saída para retorno dos dados do paciente
   - Inclui campos de preparo para prontuário e vínculo médico

5. backend/.../auth/dto/PacienteVinculoMedicoRequest.java
   - DTO para atualização direta do vínculo principal com médico (CRM)

6. backend/.../auth/service/PacienteService.java
   - Regras de negócio do módulo de pacientes:
       criar, listar (com busca), buscarPorId, atualizar, deletar
       atualizarVinculoMedico
   - Busca textual por nome, endereço e CRM de referência

7. backend/.../auth/controller/PacienteController.java
   - Controller REST com endpoints:

       GET    /api/pacientes                     → lista pacientes (admin e médico)
       GET    /api/pacientes/{id}                → detalha paciente por ID (admin e médico)
       POST   /api/pacientes                     → cria paciente (admin)
       PUT    /api/pacientes/{id}                → atualiza paciente (admin)
       PUT    /api/pacientes/{id}/vinculo-medico → atualiza vínculo com médico (admin)
       DELETE /api/pacientes/{id}                → remove paciente (admin)
